# Private Label Food Setup — USA Design Validation Workshop (Aug 2006)

## Summary

**Design Validation (DV) workshop deck**, week commencing 21 August 2006, for a US retailer's private-label food setup process. Two near-identical versions (v2 + v3) archived together — content is effectively a single workshop artefact. Part of the same 2006 IBM consulting practice as the [[Brain/wiki/secure-tesco-tom-2006|Tesco Top-Down Design]] engagement.

## Agenda

1. Product Types
2. Deployment Timeline
3. Supplier and the Technical Library
4. Process Overview

## Product Types

Four high-level product types to confirm at the workshop:

- Private Label Food
- Private Label non-Food
- Kitchen
- Branded

**Open questions:**

- Will PL non-food products be managed in the technical library?
- Will Kitchen products be managed in the technical library?

## Deployment Timeline

Launch milestones (mix of Interim / Pre-Launch / End State):

| Date | Milestone |
|---|---|
| 2 Jan | Mock Store Filled |
| 28 Feb | Begin RMS Launch |
| 21 Mar | RMS Live |
| 30 Mar | Planograms Complete |
| 2 Apr | Product File Complete |
| 4 Sept | Interim TTL Tool Live |
| 25 Sept | Bus Trip / Range 1 Sign-off |
| 30 Oct | U.S. TTL Live |

Phases: Interim → Pre-Launch → End State. Capability deployment (**Process State**) tracks through these milestones.

**RMS** = Retail Merchandising System (likely Oracle Retek RMS). **TTL** = Technical Library (product specifications database).

## Why This Matters

A representative mid-engagement artefact from the IBM pre-Secure consulting practice — specifically, a **Design Validation workshop** that sits between scoping (see [[Brain/wiki/secure-tiger-property-it|Tiger Property IT]]) and implementation build. DV workshops confirm the design choices made in scoping against stakeholder input before committing to build.

Useful as pattern precedent for:

- How to structure a workshop deck: agenda → key confirmations needed → timeline anchoring → open questions surfaced for stakeholder decision
- The gap between "Interim," "Pre-Launch," and "End State" process models — a pragmatic staging approach that lets a retailer operate on the new model incrementally rather than big-bang
- The role of a **Technical Library** (TTL) as the master data backbone for private-label product specification
