Solution Architecture

ASPEN, Application Service Provided Enterprise Notification System, is a centrally hosted Web Service that contains the Consumer Demand Signal Monitor algorithm. ASPEN can accept data from enterprise retail organizations of all sizes and scale.

 

Retail enterprise customers send Point-of-Sale (POS) transaction data to a central Biztalk Server Group. Biztalk constructs the data to be sent to the Demand Signal Monitor. The Demand Signal Monitor determines what products are out-of-stock based on the POS data from the store and sends a message back to the Biztalk Server Group.  Biztalk derives the destination, source, and message type from the data contained in the message from the Monitor. A message is then routed to a stock person working at the store where the POS data originated.

Anatomy

 

ASPEN is a hosted web service environment. Its primary function is to deliver the consumer demand signal (OOS notification) for the retail enterprise customer. It consists of a multi-server web cluster as shown in the diagram.

Windows 2000 Advanced Server Web Cluster:

 

Provide all HTTP and HTTPS connectivity.  Retail Enterprise for ASPEN.  This cluster serves as the interface to the Biztalk Server Group through ASP driven HTTPS Receive Functions.  The customer has the ability to VPN into our Web Cluster and use FTP.  This cluster will also contain the Web Interface for managing access to Demand Signal Notification Services. 

 

Biztalk Server Group Cluster:

 

Provides all message and data routing for ASPEN.  Open Channels and Message ports are used to derive transport and destination information from data contained in the incoming XML data from the Enterprise Retailer.  The transport and destination information are derived from a SQL Server 2000 database.  See CASE: Fireball Solution Capital for details of Biztalk objects.

 

Rational for using Open Message Ports and Channels:

 

“When you create a channel for an open messaging port, and the destination information is provided in the document, the inbound document definition for that channel must reference a specification that is properly configured.

 

You can use an open messaging port to send one or more standardized documents to many different current or future trading partner organizations without creating a messaging port for each destination. All documents share the same envelope, security, and transport properties that are established in the messaging port.”  Biztalk Help File

 

Application Server Cluster:

 

The Application Servers contain the Business objects required for the Demand Signal Notification System.  As well as COM+ objects for the Web Interface.

 

SQL Server / Analysis Services Cluster:

 

The SQL Server Cluster will contain the Biztalk databases for managing state.  It could also act as a repository for POS and Item promotion data into a data warehouse based on the ARTS data model fed by the IXRetail XML data model definitions.  Retail specific Business Intelligence Cubes would then be generated sold as a Web Service to the Enterprise Retail Customer. 

  

OOS Application Server Cluster

 

This cluster of servers contains the Data Ventures Demand Signal Algorithm for determining what items are out of stock for a store given POS and Item History.  Point of Sale data will be sent to this algorithm to be processed to determine what is out of stock at that store.  Then a message will be routed back to Biztalk to be sent back to SMTP pagers.
