BizTalk Framework™ Schema Description

Schema Name: Sales Transaction

Schema Type:  Document

Schema Description

The ActiveStore™ Transaction Retail Business Information (RBI) team has as its goal to collect and combine all possible transactions in the store to create a consistent business message that can be used by all consumers of any transaction.

Schema Classification Information

Starting point for the creation of the model has been the scope description and the inventory of the interactions that are possible to a POS system.  The following systems have been identified as consumers/users of Sales Transaction:

-          Sales audit

-          Time and attendance

-          Item movement (inventory)

-          Labor scheduling

-          In-store accounting

-          Promotion tracking

-          Customer frequency, loyalty, clientelling

-          Authorization

-          Security audit

-          Data warehousing

-          Return valuation (post voids, repairs, etc.)

-          Forecasting

Note:  The term POS system does not necessarily mean the actual POS device. The POS system can also include functionality that is not present on the POS device, but that is necessary to use this device.

 

Business Process Name: Point of Sale/Point of Service Transaction

 

Industry Classifications:  Retail

Prerequisite Setup Instructions

None

BizTalk Framework Envelope Data Requirements

The elements and attributes that are defined within the BizTalk Framework envelope portion of a document have not been defined at this time.

Processing Rules

The expected results of Sales Transaction exchange are one of the following:

-          Request for transaction data, with boundary parameters (e.g. elapsed time, store event).

-          Transaction data, as Sales Transaction, sent to requester.
