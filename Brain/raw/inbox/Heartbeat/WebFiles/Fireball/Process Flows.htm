Process Flows

The diagram below describes the Fireball Pilot Process.  The process begins with a data file being sent from Data Ventures (XML) which contains Out of Stock (OOS), Alarm, or Data Flow alarms. A file from Data Ventures will only contain one type of data.  Meaning a file will never arrive at the Biztalk Server containing both alarms and OOS data.

 

The destination of the message is contained in the database.  The preprocessors derive those addresses based on information contained in the XML message.

 

Messages are finally routed to an SMTP Address which could be a pager or an email client.


 


RIO Inputs

Each Retailer will have its own methods and systems for collecting and storing Point-of-Sale (POS) transaction data and their item and promotional data.  Some retailers will have a centralized spoke hub model; some will have a decentralized model.  The main goal of RIO inputs is to understand the retailer's data and to translate this data into an XML format for transfer into ASPEN.  Analysis and understanding the structure and definition of data is critical to the success of RIO Inputs. 

 

The following files contain, respectively, the XML schema and an instance of the data required by ASPEN:

 

POS.xml

POSInstance.xml

 

If additional data integration is required, the Biztalk Sales Transaction Schema described by the Activestore initiative is useful.
