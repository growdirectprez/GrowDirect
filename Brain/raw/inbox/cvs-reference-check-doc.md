CVS Reference Check

Leo Hartnett – Vice President of ECR
October 31st , 2003 4pm

CVS implemented E3 (TRIM) in 1993.  Spent 1 year planning for the implementation, began the implementation in October and were up in running in February (6 months to implement)
16 concurrent users on E3
Used Inforem prior to implementing E3
E3 is used to replenish warehouses only (9 DC’s)
200,000 SKU / Location combinations
An in-house system (AIM) is used to replenish front and back store but not direct store delivery
In the process of looking at advanced store replenishment with JDA
Currently store replenishment is decentralized, looking to centralize store replenishment
Did not have any information on Intactix implementation
Implemented JDA’s marketplace in April 2002
Internet security was a major issue due to external dial-ups into the system, a lot of testing was required
Implemented improved hardware to run marketplace (AS 400, Model 820, 5.1 operating system, “TechIT” security, portal certificates
Marketplace is  being hosted on demand
3-4 months to implement Marketplace, security issues, looking back doors
Main security issues was enabling suppliers to have visibility to their data securely
13 users of marketplace at CVS, 17 suppliers through marketplace
Good relationship with JDA
Looking at Advanced Replenishment with JDA
IT dies not like JDA, another platform to support, users like JDA
Little / no AS/400 experience in house
JDA has been extremely responsive
When E3 was implemented in 1993, minor customizations were performed on E3 – account for reserve inventories
Functionality is now built into the software, currently trying to remove custom code
On upgrades, CVS is generally 6 months behind current upgrade
Keep it as vanilla as possible, faster install
JDA provided implementation support
Sent users to JDA/E3 school
Worthwhile learning business concepts and advanced concepts
Spent a week training suppliers (ensure supplier is up to speed)
JDA is in the process of building an interactive online, online training course (is better than anyone else on the market)
Used some of JDA’s methodology but made up most of their own methodology
Marketplace was implemented using:
2 IS FTEs
2-3 IT FTEs
1 Project Lead
1 Executive Sponsor
1 Business Lead
2-3 Users
Wrote test scripts and user acceptance tests – JDA helped a bit
Large project, keep it simple, “see a snake, whack it with a stick”
Understand processes up front (1 year of analysis, 6 months to implement)
Cost $1M in 1993 to implement E3 – Hardware, software and implementation
Some overlap in functionality between Marketplace and E3
JDA should combine the products together
JDA tells it like it is – honest, what is real today and what they are working on
JDA is widely deployed software
Do not go with SAP
SAP is rich in functionality
Designed for manufacturing
Looked at it in 1998-1999
Big bang install required
Could not scale in retail environment (280 servers)
Initially were sold on Retek
Retek promises were different than reality
Retek was a highly integrated big bang install
Internal integration (GIS) from Sterling
Considering advanced replenishment at a store level between 200,000,000 Store-SKU combinations and 360,000,000 Store-SKU combinations for 4,100 stores
Maintaining inventory at store level
Inventory application is separate from dispensary
Using Excel and Access for planning
Built an internal planning system
Arthur couldn’t scale to SKU-location volumes
Arthur is a medium to small tier player
Wal-mart used to use Arthur, replaced it with their own application
