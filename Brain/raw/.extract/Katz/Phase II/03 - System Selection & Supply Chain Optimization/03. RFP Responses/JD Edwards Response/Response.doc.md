Product Integration (3.3.2)
Please describe the integration capability of your solution with external applications.  What features of your solution make it a good fit in a multi-application environment?

J.D. Edwards has full integration capabilities with its product called eXtended Process Integration or XPI for short.

XPI is a suite of technologies that allow you to assemble a portfolio of applications, link processes with trading partners, and integrate workflow engines so that the right process links to the right application and the right information gets to the right person at the right time.

XPI provides the infrastructure for both internal and external (B2B) collaboration. The internal component, XPIe, provides all the enterprise application integration (EAI) components required for high performance, real time internal collaboration. XPIe integrates seamlessly with the external or B2B component, XPIx. XPIx provides all the external workflow, security and standards-based elements required for safe and secure collaboration beyond the traditional four walls. 

J.D. Edwards has moved beyond EAI and created a solution that will not only integrate internal systems but also will allow B2B collaboration through disparate systems, applications, and platforms. XPI helps organizations catch the next wave of business — extending beyond the enterprise to collaborate more effectively with customers and suppliers. 

The standard industry approach to collaborative commerce is to provide point-to-point solutions, such as trading communities, exchanges, and marketplaces. Point-to-point solutions can mandate undesirable third-party intervention and provide very little integration and no universal connectivity. To avoid these pitfalls, J.D. Edwards has built its collaborative commerce vision on both its OneWorld enterprise and supply chain software, and its extended integration capabilities provided through XPI. 

XPI uses a component-based message broker technology to integrate various enterprise applications and enable internal and B2B interoperability. We are leading the industry by providing a unique combination of technology (XPI) and applications, so our customers have the distinct advantage of implementing a complete collaborative solution.

Data Architecture (4.1.8)
Please provide diagrams and narrative (including tools and products used) that detail the Data Architecture that your proposed solution employs.

J.D. Edwards uses a normalized approach to its Data Architecture. 

Normalization is a series of steps followed to obtain a database design that allows for efficient access and storage of data in a relational database. These steps reduce data redundancy and the chances of data becoming inconsistent. A table is said to be normalized if it satisfies certain constraints.

A row is in first normal form if and only if all underlying domains contain atomic values only. 1NF eliminates repeating groups by putting each into a separate table and connecting them with a one-to-many relationship. A row is in second normal form if and only if it is in first normal form and every non-key attribute is fully dependent on the key. 2NF eliminates functional dependencies on a partial key by putting the fields in a separate table from those that are dependent on the whole key. A row is in third normal form if and only if it is in second normal form and every non-key attribute is non-transitively dependent on the primary key. 3NF eliminates functional dependencies on non-key fields by putting them in a separate table. At this stage, all non-key fields are dependent on the key, the whole key and nothing but the key.

 Data Loads (4.1.14)
Please describe how data is initially loaded into the system during implementation and ongoing activities. For example, new module, new application, etc.
There are a variety of ways of initially loading data into the system and ongoing importing of data:

Z-Files – Batch – J.D. Edwards has created a shadow copy of its database files called Z-Files.  These files can be thought of as “interim” tables that can be populated in a flat file format.  These files can then be imported into the J.D. Edwards production databases via a batch process.  All of the rules associated with data entry, i.e. validation, etc. will be applied to the data in these tables when moved into the production database.  Exceptions, records that do not meet data entry criteria, are not updated and are flagged for review.
API – Batch, Near Real Time, Real Time - J.D. Edwards provides a full C compatible API set that can be used to create applications for data loading connectivity.
APAg – Advanced Planning Agent – Batch, Near Real Time, Real Time – The Advanced Planning Agent is part of J.D. Edwards APS (Advanced Planning Solution) Suite of products and is a resource that can be set up to transfer and translate data from multiple sources to multiple destinations.  Rules and scripts can be established to handle non-standard data transfers.  This agent can also be set to run at certain time intervals or in a real-time mode.
ETL – Extract, Transform and Load – Batch, Near Real Time, Real time – The ETL tool is part of J.D. Edwards Business Intelligence (BI) product line. Like APAg it allows incremental loading of data.  Mappings and mapplets along with session tasks are utilized to transform the data.  Supported data types include ODBC, CIFS/NFS, COBOL COMP/COMP-3/COMP-6 VSAM, XML Schema.
TCU – Table Conversion Utility – Batch – This is a graphical utility that allows users to create Wizard type applications to update Z-Files.  These Wizards can be saved and reused at any time.
Data Roadmap – Batch – This graphical tool utilizes spreadsheets and a J.D. Edwards tool called AutoPilot.  Spreadsheets are populated with data and a script is executed against the spreadsheet.  This script mimics a person performing data entry on J.D. Edwards’s data entry screens.
Xpi – extended Process Integration – Batch, Real Time, Near Real Time.  Xpi is a technology that utilizes adapters and a common broker to send and receive data from a variety of sources.  Working with XML and Java, data is transformed into messages.  These messages are then translated into a common format and sent to the messaging broker.  The broker then publishes this information, in real time, to any appropriate adapter.  Since the information is in a common format, the adapter can then take this information and format it for any other system.  One of the most important aspects of Xpi is that J.D. Edwards has built all of the integration brokers, called Xbp’s, to perform the data transformation for our customers.  These brokers can be thought of as J.D. Edwards applications without the screen interface.  This means any validations are automatically performed on any data coming over the broker before being stored in the database.   There are also several adapters already created for the most popular applications.

Workflow (4.1.16)
Describe the workflow processes that are available with your solution / application / system.  What tools are used to implement the workflow process?  How is the client notified that they have a task to perform and how is that task “delivered” to them?  How many levels of approval are available?

A workflow process consists of tasks and transitions. A task represents an action that takes place in the workflow process, such as starting a workflow process, sending an approval message, or updating a table in a database. A transition links workflow tasks together.  Transitions can contain transition conditions, which are logical criteria that determine which task will occur next in the workflow process.

Below is a sample Workflow process:



 EMBED PBrush  

Workflow system 
All of the tools that facilitate the design of a workflow process, as well as the workflow engine.
Workflow engine 
All of the J.D. Edwards ERP mechanisms that move the workflow process from one task to another.
Process definition 
A template or model of the workflow process. The process definition contains all the information about the tasks, transitions, and conditions that make up a workflow process. That is, the process definition defines each component of the process and defines each path the process might follow.
Process instance 
An active process in the system. When an event rule activates a workflow process, the system creates a process instance. The process instance follows a path that is defined in the process definition. You can have several concurrent process instances of the same process in the system.
Note
If you are familiar with object-oriented programming, a process definition is comparable to a class and the process instance is comparable to an object.
Process version 
A specific workflow process definition. The system uses process versions to allow for the modification of processes without disrupting currently running process instances. Before you modify a process, you should copy the workflow process version to a new version number, edit the new version, and then make the new version active. Use this versioning mechanism during workflow development to allow process instances that started using the old version to finish using that same version.

J.D. Edwards Workflow Tools (Workflow) give you the ability to do the following:
• Attach a workflow process with event rules to any event within an application, batch process, or named event rule (NER). You can also attach a workflow process through table event rules in Table Design Aid.
• Execute conditional processing, which is logic contingent upon supplied criteria, such as quantity and dollar amount. This criterion can be any parameter used in the decision-making process that the system can evaluate.
• Create messages specific to the process by setting up message templates (text substitution messages) in the data dictionary.
Workflow also:
• Integrates seamlessly with J.D. Edwards ERP interactive and batch applications
• Offers multiple level approvals
• Offers automatic escalation of messages, which have not been acted upon
• Offers manual escalation of processes in which the administrator has the ability to override or bypass certain tasks or users in the workflow process
• Automatically time stamps all tasks within a process for auditing and improvement analysis through the Process Task Monitor or Workflow Advanced Analysis.

All of the technology, rules, and principles explained above allow you to work more efficiently and reduce cycle time. The automated process reduces errors and generates less paperwork. Furthermore, Workflow helps you develop workflow-enabled applications or quickly and smoothly enable existing applications for workflow. You have the ability to attach a workflow process that sends a message or calls an application to any event within an application. All you have to do is attach a Start Process call to an event within an application to initiate the workflow process. Because this process is defined outside of your application, it offers you unlimited flexibility to incorporate your innovative ideas into the J.D. Edwards ERP system.

 Security Architecture (4.1.21)
Please provide diagrams and narrative (including tools and products used) that detail the Security Architecture that your proposed solution employs.  Describe how the solution/application/system structures users so that a user has access to see only what they are allowed to see and change only what they are allowed to change.

Security is built into J.D. Edwards’s products.

User security tells the software who has access to log into the application.  Users can be stand alone or added to groups that have specific security access.

Within the application J.D. Edwards provides a Security Workbench.  This tool allows administrators to set security rights for individual users, groups of users or all users down to the field level.  This ensures that users can only see data that is accessible to them.

ERP 9.0 security enables a security administrator to control security for individual users and for groups of users. The security administrator can control (secure or unsecure) users and groups from the following features:
• Application security
Controls access to or installation of specific applications.
• Action security
Controls the ability to perform specific actions, such as adding, changing, deleting, selecting, or copying.
• Table row security
Controls access to a specific list or range of records within a table.
• Column security
Controls access to a specific column within a table. Columns are represented in ERP 9.0 as a field on a form or report. Column security can be set on a table, form, or application.
• Processing option security
Controls whether users can view or change the values for processing options, which affects how the associated application works. It also controls whether users are allowed to prompt for versions of that application.
• Tab security
Controls access to tabs on a form.
• Exit security
Controls access to the menu bar exits on forms.
• Exclusive application security
Controls access to secured information using one exclusive application.
• External calls security
Controls access to external call applications.
• Solution Explorer security
Controls access to Solution Explorer features.
• Miscellaneous security
Controls Read Only Reports and Workflow status monitoring.
• User signon and database security
Prevents user access to the database from outside of ERP 9.0.
• Portal security
Controls access to Portal components.

Understanding How ERP 9.0 Checks Security
When a user attempts to access an application or perform an action, ERP 9.0 checks for any security for that particular user ID. If security exists for that individual user ID, ERP 9.0 displays a message informing the user that he or she cannot proceed.  If that User ID has no security, ERP 9.0 checks the role profiles (if that user is part of a specific role), and then*PUBLIC, for security. If no security is established at any of these levels, ERP 9.0 lets the user continue.
ERP 9.0 also provides software license security through protection codes, and requires user validation at signon and when accessing new data sources.

At specific object levels, you can set the following levels of security, alone or in any combination, for users and groups:

Application security
Secures users from running, installing, or both, a particular application or a particular form within an application.
Action security 
Secures users from executing a particular action, such as adding, deleting, revising, inquiring, or copying a record.
Row security 
Secures users from accessing a particular range or list of records in any table.
For example, if you secure a user from accessing data about business units 1 through 10, the user cannot view the records that pertain to those business units.
Column security 
Secures users from viewing a particular field or changing a value for a particular field.  This item can be a database or non-database field that is defined in the data dictionary, such as the work/calculated fields.
For example, if you secure a user from viewing the Salary field on the Employee Master application, the Salary field does not appear on the form when that user accesses that application.
Processing option security
Secures users from viewing or changing the values of processing options, or from prompting for versions and prompting for values for specific applications.
For example, if you secure a user from changing the processing options for Address Book Revisions, the user could still view the processing options (if you did not secure the user from prompting for values) but would not be able to change any of the values.  If you secure a user from prompting for versions, the user would not be able to see the versions for a specific application, so the user would not be able to choose a different version of an application from the version that the administrator assigned.
Tab security 
Secures users from viewing or changing fields in a tab or tabs on a given form.
Exit security 
Secures users from menu bar exits on ERP 9.0 forms. These exits call applications and allow users to manipulate data. Exit security also restricts use of the same menu options.
Exclusive application security
Overrides row security that is set for an application. When you set exclusive application security for a user, the system overrides row security for every table that is accessed by the application that is specified. All other security still applies.
External calls security
Secures users from accessing standalone executables that exist external to ERP 9.0.  These external executables, which might include design tools, system monitors, and debugging tools, are specific to ERP 9.0.
Solution Explorer security
Secures users from accessing or making changes to the following Solution Explorer features: Solution Explorer Portal, Task Documentation, Fine Cut, Favorites, Solution Explorer, Rough Cut, and Universal Director.


Miscellaneous security
Miscellaneous security controls two separate functions: Read Only reports and Workflow Status monitoring. Read Only Reports denies access to table I/O and business functions, and prevents users from writing to tables. Workflow Status monitors and controls access to the workflow status.

ERP 9.0 security is at the object level. This level means that you can secure specific objects within ERP 9.0, which provides flexibility and integrity for your security. For example, you can secure a user from a specific form; then no matter how the user tries to access the form (using a menu or any application that calls that form), ERP 9.0 prevents him or her from accessing that form. Though setting up good security is always a challenge, ERP 9.0 simplifies the process by allowing you to set security for hundreds of objects at a time by securing all objects on a specific menu, or securing all objects under a specific system code.  But remember, only the objects are secured; ERP 9.0 does not support menu or system code security. Object security provides a higher integrity. For example, if you were to secure a specific menu to prevent users from accessing the applications on that menu, the users might still be able to access those applications through some other menu or some other application that accesses those applications that you were trying to secure.

Application Programming Interfaces (4.2.5)
List and describe what Application Programming Interfaces (APIs) or Import / Export Managers are available with your solution / application / system to put data into the database and retrieve data.

There are a variety of ways of loading data into the system and ongoing importing/exporting of data:
1.	Z-Files – Batch – J.D. Edwards has created a shadow copy of its database files called Z-Files.  These files can be thought of as “interim” tables that can be populated in a flat file format.  These files can then be imported into the J.D. Edwards production databases via a batch process.  All of the rules associated with data entry, i.e. validation, etc. will be applied to the data in these tables when moved into the production database.  Exceptions, records that do not meet data entry criteria, are not updated and are flagged for review.
2.	API – Batch, Near Real Time, Real Time - J.D. Edwards provides a full C compatible API set that can be used to create applications for data loading connectivity.
3.	APAg – Advanced Planning Agent – Batch, Near Real Time, Real Time – The Advanced Planning Agent is part of J.D. Edwards APS (Advanced Planning Solution) Suite of products and is a resource that can be set up to transfer and translate data from multiple sources to multiple destinations.  Rules and scripts can be established to handle non-standard data transfers.  This agent can also be set to run at certain time intervals or in a real-time mode.
4.	ETL – Extract, Transform and Load – Batch, Near Real Time, Real time – The ETL tool is part of J.D. Edwards Business Intelligence (BI) product line. Like APAg it allows incremental loading of data.  Mappings and mapplets along with session tasks are utilized to transform the data.  Supported data types include ODBC, CIFS/NFS, COBOL COMP/COMP-3/COMP-6 VSAM, XML Schema.
5.	TCU – Table Conversion Utility – Batch – This is a graphical utility that allows users to create Wizard type applications to update Z-Files.  These Wizards can be saved and reused at any time.
6.	Data Roadmap – Batch – This graphical tool utilizes spreadsheets and a J.D. Edwards tool called AutoPilot.  Spreadsheets are populated with data and a script is executed against the spreadsheet.  This script mimics a person performing data entry on J.D. Edwards’s data entry screens.
7.	Xpi – eXtended Process Integration – Batch, Real Time, Near Real Time.  Xpi is a technology that utilizes adapters and a common broker to send and receive data from a variety of sources.  Working with XML and Java, data is transformed into messages.  These messages are then translated into a common format and sent to the messaging broker.  The broker then publishes this information, in real time, to any appropriate adapter.  Since the information is in a common format, the adapter can then take this information and format it for any other system.  One of the most important aspects of Xpi is that J.D. Edwards has built all of the integration brokers, called Xbp’s, to perform the data transformation for our customers.  These brokers can be thought of as J.D. Edwards' applications without the screen interface.  This means any validations are automatically performed on any data coming over the broker before being stored in the database.   There are also several adapters already created for the most popular applications.

1
Since the JD Edwards solutions are used with potentially thousands of users, record locking is not generally used, except in cases of data dependencies.  JD Edwards software uses a “last in” philosophy of data access.  For example, if user 1 and user 2 were both updating a customer’s telephone number, only the last user to press ‘OK’ would have their information saved. Additional System Capabilities

Data Collection

PeopleSoft Enterprise One supports data collection via a partner solution.  We have multiple partners who provide solutions in this area. International Business Machines Corporation (IBM) offers data collection and communications software solutions for enterprise-wide data collection initiatives.  This solution has certified integration between PeopleSoft Enterprise One and IBM’s ERPBridge Version 2 product.   The ERPBridge for PeopleSoft Enterprise One product is an interactive interface between Enterprise One and the IBM data collection solution, DCConnect. This product enables the collection of transaction data required for inventory, distribution, shop floor control and advanced warehousing applications with the use of IBM and non-IBM fixed and portable data collection terminals.  Data can be entered at the source, on the plant floor or in the warehouse, as the activity occurs.  The system provides real-time updates to Enterprise One using standard supported APIs, or stores collected data when Enterprise One is not available.  

Supply Chain Management

We have included some information on supply chain management applications that may be of interest as Katz evaluates the requirements of other business units within the organization.  

Warehouse Management
PeopleSoft Enterprise One Warehouse Management provides the flexible, automated warehouse support for better customer service and lower operating costs. Advanced rules-based stock location and directed movement logic dramatically improves warehouse labor efficiency and space utilization. Our Warehouse Management solution is fully integrated with sales, purchasing, manufacturing, and transportation. 

Transportation Management
PeopleSoft Enterprise One Transportation Management provides an integrated logistics function to cost-effectively plan, arrange, and track the distribution and delivery of your products. Multiple shipping types including truckload (TL), less-than-truckload (LTL), multi-modal, private fleet, courier, or public carrier.  Our Transportation Management solution is fully integrated with sales, purchasing, warehousing and financials.  All costs associated with every aspect of every shipment can be tied directly back to the responsible activity.

Manufacturing Management
PeopleSoft Enterprise One Shop Floor Management executes the production plan that supports inventory, cost, quality, and product lead-time objectives to meet customer and marketplace requirements. It efficiently schedules work-in-process and creates the needed parts list and routings. The scheduling workbench provides a variety of online options useful for work order management. The scheduling functionality shows work center information (dispatch list) for work orders, including operation sequence, open orders, and run hours by machine and labor.

Customer Relationship Management

Sales Force Automation
PeopleSoft Enterprise One Sales Force Automation offers Web-based functionality that helps capture all relevant information on prospects and customers. It is designed to support sales staff and provide management with revenue and pipeline information. On an account level, sales representatives can keep track of contacts, activities, and all interactions (whether phone, e-mail, or face-to-face meetings), as well as details on each customer’s product and service needs.  Sales Force Automation is available in both wireless and disconnected modes.  Through wireless connectively on popular devices (including Palm, Blackberry, Pocket PCs and WAP-enabled devices), sales professionals have real-time access to the critical information needed to close the deal and drive customer loyalty

Marketing Automation
PeopleSoft Enterprise One Marketing Automation offers Web-based functionality that allows you to create and track campaigns and marketing programs. It captures all costs and tracks all the resulting leads from various activities. Successful sales can be directly tied to specific marketing campaigns, providing a view into the profitability of your marketing activities. Your marketers also can improve their effectiveness by analyzing campaign results. 

Contact Centre
PeopleSoft Enterprise One Contact Center provides access to all of the customer information needed to satisfy the customer — including billing, sales and service orders, service requests, entitlements, recent interactions, and even suggested products to cross-sell and up-sell. Multi-channel interaction management enables the Contact Center to receive, prioritize, and manage customer interactions across all channels including voice, voice over IP, e-mail, and Web collaboration.
