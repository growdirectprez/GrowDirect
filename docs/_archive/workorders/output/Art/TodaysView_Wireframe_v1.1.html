AC-A7

7. Accessibility (WCAG 2.1 AA)

  • All interactive elements have min-height: 44px and min-width: 44px touch targets
  • Color is never the only state indicator: severity communicated via label text + color
  • Contrast ratios: #E5E7EB on #0D1117 = 13.1:1 (AAA). #FBBF24 on #0D1117 = 10.1:1 (AAA). #6B7280 on #0D1117 = 4.6:1 (AA).
  • All images have aria-hidden="true" (decorative) or aria-label (functional)
  • Cards use role="button" and tabindex="0" for keyboard navigation
  • Health bar uses role="img" with descriptive aria-label
  • Animations respect prefers-reduced-motion (add in production: disable all CSS animations)
  • v1.1: SVG icons use aria-hidden="true" (decorative). Nav items and action cards carry the semantic label. Chirp peek has descriptive aria-label including Chirp title.

8. HTMX Integration Points

HTMX

  • hx-get="/api/today-view" on page load → populates greeting, Chirp count, hero, peek, cards
  • hx-get="/api/chirp/{id}" on hero banner → gets Chirp detail before wizard launch
  • hx-get="/wizard/step/{process}/1" on card/hero tap → opens full-screen wizard overlay
  • hx-get="/companion/chirps" on chirp peek tap → navigates to Chirps tab view
  • hx-trigger="load" on hero banner for real-time Chirp refresh
  • All swaps target #wizard-container (full-screen overlay, not shown in this wireframe)
  • No full page reloads. All transitions via HTMX swap + Alpine.js micro-transitions

9. Data Sources (CRDM Mapping)

  • Greeting: canary_app.merchants.merchant_name + server clock
  • Chirp count: canary_app.alerts WHERE status = 'ACTIVE' AND merchant_id = ?
  • Hero Chirp: canary_app.alerts ORDER BY severity DESC, created_at DESC LIMIT 1
  • Chirp peek: canary_app.alerts ORDER BY severity DESC, created_at DESC LIMIT 1 OFFSET 1 (second-priority Chirp title)
  • Action cards: Server logic combining detection_rules, cash_drawer_shifts, daily_metrics, and time-of-day
  • Health bar: Aggregate from canary_metrics.daily_metrics + active alert severity distribution
