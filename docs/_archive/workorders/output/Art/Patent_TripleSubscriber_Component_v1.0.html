Ingestion Layer

Source Network (Any Webhook Provider)

Square, Shopify, Epic, FedEx, or any system capable of HTTP POST webhooks. Generates events with UUID identifiers and signs payloads with HMAC-SHA256.
HTTPS POST + HMAC-SHA256
↓ raw webhook payload + signature ↓

API Gateway / Webhook Receiver

Validates HMAC signature. Computes SHA-256 hash of raw payload. Assigns event ID. Publishes to message queue. Returns 200 OK. Single entry point — all events enter here.
Node.js + Express
Queue Layer — Critical Path

Message Queue (Durable, Ordered)

Fan-out point. Three independent consumer groups. At-least-once delivery. Message ordering within merchant partition. Each subscriber tracks its own offset independently.
Valkey Streams · Signal Yellow
Subscriber Layer — Triple Independent Consumers

Sub 1: Hash & Seal

Write-once evidence store. SHA-256 hash + hash chain link. Append-only — never altered, never deleted. Bilateral verification source.
PostgreSQL JSONB · Write-Once

Sub 2: Parse & Route

Structured schema. Queryable, indexed. Mutable — enrichment allowed. Replayable from Sub 1. Emits to detection engine.
PostgreSQL Tables · Partitioned

Sub 3: Merkle & Ordinal

Batch hash accumulator. Merkle tree construction. Ordinal inscription. Key custody. Bitcoin base layer anchoring.
Node.js Worker · Bitcoin Core
Persistence Layer

Evidence Store

Immutable ledger. JSONB raw payloads. Hash chains. UNIQUE constraint prevents duplicates. Source of truth for bilateral verification and replay/rebuild.
PostgreSQL JSONB · Deep Blue

Structured Store

Queryable business data. Partitioned by merchant_id. Indexed for search. Feeds dashboard and analytics. Derivable from evidence store.
PostgreSQL Tables · Partitioned

Ordinal Pool Registry

Inscription IDs. Merkle proof paths. Bitcoin block references. Pool utilization tracking. Key custody records.
PostgreSQL + Bitcoin Core
Application & Revenue Layer

Detection Engine + Dashboard

Rule evaluation against parsed events. Real-time alerts via WebSocket. Merchant-facing dashboard with evidence view. Loss prevention, anomaly detection, pattern matching.
Node.js · React Frontend

Validation API (L402 Sat-Gated)

HTTP 402 → Lightning invoice → sat payment → validation response. Returns: verification status, block number, Merkle proof, inscription ID, timestamp. Perpetual revenue per verification.
L402 · Lightning Network
External Verification (No Trust Required)

Bilateral Verification Path

Source network compares its send log against evidence store hash. Merkle proof path verifiable on any Bitcoin block explorer. No intermediary required. Survives total system failure — Bitcoin anchor is independent.
