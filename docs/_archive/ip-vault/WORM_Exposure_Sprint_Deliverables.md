#### **Technical Performance**

**Mobile Responsiveness**:
- [ ] Viewport meta tag present: `<meta name="viewport" content="width=device-width, initial-scale=1.0">`
- [ ] Mobile-first CSS approach
- [ ] Touch targets >= 48px (buttons, links, form inputs)
- [ ] No horizontal scrolling on mobile
- [ ] Font size >= 16px for body text
- [ ] Test on real devices: iPhone, Android (Chrome DevTools + BrowserStack)

**Core Web Vitals Targets**:
- **LCP (Largest Contentful Paint)**: < 2.5s
  - Optimize hero image (WebP + lazy loading)
  - Defer non-critical JS
  - Minimize CSS blocking
- **FID (First Input Delay)**: < 100ms
  - Minimize main thread work
  - Break long JS tasks into chunks
- **CLS (Cumulative Layout Shift)**: < 0.1
  - Reserve space for images/videos
  - Avoid dynamic content insertion above fold
  - Set explicit dimensions on media

**Page Speed Optimizations**:
- [ ] Image optimization: WebP format, srcset for responsive, lazy loading
- [ ] CSS minification & critical CSS inlined
- [ ] JS minification & code splitting
- [ ] CDN for static assets
- [ ] Gzip compression enabled
- [ ] Browser caching headers configured
- [ ] Lighthouse score target: >= 90

**Mobile Optimization**:
- [ ] Responsive design tested at 320px, 768px, 1024px+
- [ ] Touch-friendly form inputs
- [ ] Fast mobile load (PageSpeed Mobile score >= 85)
- [ ] No intrusive interstitials above fold

### Template for Helpful Reply (Non-Sales Pitch)

```markdown
Great question — this is something a lot of Square merchants run into.

**Here's what I'd check first:**
1. [Diagnostic step relevant to their issue]
2. [Diagnostic step relevant to their issue]
3. [Diagnostic step relevant to their issue]

**Why this happens:**
[Brief explanation of root cause — validate their pain]

**In the meantime:**
[Practical immediate workaround or manual process]

**Longer-term:**
This is actually a pretty common gap in Square's native reporting.
A lot of folks end up building custom spreadsheets or looking into tools
that auto-flag these patterns so you're not manually digging through transactions
every week. Might be worth exploring if this is a recurring headache for your team.

Happy to help if you run into anything else — feel free to DM if you want to chat
more about process improvements.
```

**Key Elements**:
- ✓ Diagnostic/actionable advice (solves immediate problem)
- ✓ Validates their pain ("a lot of merchants run into this")
- ✓ Explains root cause (shows expertise)
- ✓ Offers manual workaround (helpful now)
- ✓ **Soft positioning**: "tools that auto-flag" (not sales pitch; mentions category)
- ✓ Doesn't mention Canary by name (let credibility speak)
- ✓ Open-ended ("feel free to DM") — gives pathway if they want to learn more
- ✗ No product links, no pricing, no "sign up" CTA
