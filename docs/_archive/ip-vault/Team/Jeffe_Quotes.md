### 2026-03-23 — The DOME: L402-Gated DAO Architecture

> "If our assumption is that we want to L402-gate the application to create the DOME — and every entry in the namespace gets a RaaS UUID, an ordinal, and a Lightning wallet address — we seed that wallet with satoshis as gas fees to drive the internal plumbing. It's all usage-driven and payment-gated. When we create the subscription layer, we're just funding the liquidity pool for the whole thing. We could actually make the whole thing a DAO where merchants are all agreeing to participate."

**Context:** Connecting the authentication/device identity discussion to the full Bitcoin-native economic model. Every entity in Canary (merchant, transaction, alert, case) becomes a payment channel. Subscriptions become liquidity pool funding. Merchants become DAO members, not customers.

### 2026-03-23 — Genesis Pool & Metered MCP Economics

> "We can track usage at the microservice MCP tool layer and pay to play internally for every handoff. If we abstract the GrowDirect DAO liquidity pool away from the internal Canary L402 gateways, we can provide funding to certain services like deep search or more complex agentic capabilities that are evolving every second. If we have this capability from day one we can turn it on for free and fund it through our API tokens, but when we get scale we can flip it to other stacks, solutions, and fee structures seamlessly. For now we use our own genesis pool and corp treasury to create the wallets and fund them for beta customers — try before you buy — making sure each merchant has enough funding to cover the fees until they start paying themselves."

**Context:** Extending the DOME architecture to the MCP tool dispatch layer. Every tool call between services is a metered Lightning micro-payment. GrowDirect seeds a genesis pool from corp treasury to fund beta merchant wallets. The L402 gateway is abstracted from the liquidity source — allowing seamless transition from free beta to paid production without changing the plumbing.
**Source:** GRO-326 QA agent session — follow-up to DOME/L402 architecture discussion
**Use Case:** Investor deck (go-to-market / tokenomics), whitepaper (economic model), patent filing (metered MCP dispatch)
**Keywords:** MCP metering, L402 gateway, genesis pool, liquidity abstraction, try-before-you-buy, corp treasury, agentic economics
**Tone:** Visionary, strategic, go-to-market
