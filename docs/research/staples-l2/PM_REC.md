Performance Monitoring Recommendations
Operational processes feed the transaction repository. Each process provides for data quality control. Each process should provide its own control reporting, e.g., receiving exceptions.
Store Inventory Management (SIM) is shown as a separate operational input process. SIM typically deals with the following transactions subject to approval:
Returns to DC
Transfer (store to store)
Inventory adjustment
Receiving is covered by location receiving for:
Drop shipment
DC shipments
The approvals associated with the SIM transactions are:
Returns - merchandising
Transfer
Merchandising
Field management
Inventory adjustment
Merchandising
Inventory control
Performance Monitoring Recommendations (Continued)
Transaction management organizes and maintains transactions to support direct reporting / display of operational information and to feed summary data bases.
Stock status / ledger is a key summary database for both operational support and control as well as reporting. It does the following:
It maintains the perpetual inventory at an item-location level
It provides a stock ledger based on units and currency values which coincides with period (usually weekly) financial cut-offs.
Key transactions feeding stock status / ledger include:
Receipts
Transfers
Inventory / inventory adjustment
Summary performance databases are created based on the following:
Speed of reporting is critical
History is required
Reporting is not particularly sensitive to transaction maintenance.
For summary databases like stock status / ledger, transaction maintenance must flow through to the database.
Vendor compliance monitoring would be an example of a possible application of a summary performance database.
Performance Monitoring Recommendations (Continued)
History management links with reference data management to ensure the when required, historical reports can reference the then-current version of such things as merchandise class.
Retention cycles vary depending upon major cycles in the business and legal requirements.
Reports and inquiries rely on reference data management to provide descriptive data for reports. Reports and inquires are classified as follows:
Standards
Regular and automatic
On request
For example, in merchandise management, best practice is to:
Receive regular weekly standard reports on sales, margin and inventory. The standard reports provide the basic 
scorecard
The starting level for reports and inquiries depends on the user, e.g., buyers would start at the department level.
Users may drill down to lower levels:
Using exception highlighting
User-directed
Initiate requestable standard inquiries to further deal with exceptions.
Initiate ad hoc inquiries to deal with other exceptions
