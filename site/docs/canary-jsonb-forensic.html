Executive Summary

We're sitting on a goldmine and only mining the surface. Every Square webhook that hits Canary carries a rich JSONB payload — device fingerprints, risk evaluations, card verification results, entry method signals, processing timelines, and application metadata. Today, we extract 10 fields and store the rest as an unstructured blob. That's like a detective collecting evidence at a crime scene and only photographing the front door.

The old LP world was a security guard watching CCTV, hoping to catch someone stuffing merchandise in their jacket. The new LP world is a digital private investigator — cross-referencing device IDs, tracking card fingerprints across locations, analyzing transaction velocity by terminal, detecting authorization pattern anomalies, and flagging risk score spikes in real-time. The data for all of this is already in our JSONB payload. We just need to crack it open.

This report maps every field in the Square Payment and Order webhook payloads, identifies which ones are fraud-relevant "digital evidence," proposes a tiered extraction strategy, and designs a schema drift detection system that alerts us when Square (or any future vendor) adds new fields — because those new fields might be exactly the fraud signals we need.

Key Insight
Square is literally handing us risk evaluations (risk_evaluation.risk_level), device fingerprints (device_id), card fingerprints (card.fingerprint), and CVV/AVS results. We're not reading any of it.

Section 3: Schema Drift Detection System

3.1 The Problem

Square evolves its API continuously. New fields appear in webhook payloads without advance notice. Some of those new fields might be exactly the fraud signal we need. If Square adds a new risk indicator, a new device property, or a new payment method type, we need to know immediately — not six months later in a code review.

The same applies when we add Clover, Lightspeed, Toast, or any other POS vendor. Each one will have its own payload format that evolves independently. Without a schema tracking system, we're blind to vendor changes.

3.2 The Design: Payload Schema Registry

The solution: a schema fingerprinting system that tracks the structure of every incoming webhook. When a new field appears, we detect it immediately, log it, and alert the team.

Core Algorithm: Schema Fingerprinting

Python: Extract Schema Fingerprint from JSONB
def extract_schema_fingerprint(payload, prefix=''):
    """Recursively extract field names and types from a JSONB payload."""
    schema = {}
    if isinstance(payload, dict):
        for key, value in sorted(payload.items()):
            full_path = f"{prefix}.{key}" if prefix else key
            if isinstance(value, dict):
                schema[full_path] = 'object'
                schema.update(extract_schema_fingerprint(value, full_path))
            elif isinstance(value, list):
                schema[full_path] = 'array'
                if value and isinstance(value[0], dict):
                    schema.update(extract_schema_fingerprint(value[0], f"{full_path}[]"))
            elif isinstance(value, bool):
                schema[full_path] = 'boolean'
            elif isinstance(value, int):
                schema[full_path] = 'integer'
            elif isinstance(value, float):
                schema[full_path] = 'float'
            elif value is None:
                schema[full_path] = 'null'
            else:
                schema[full_path] = 'string'
    return schema
Python: Detect Schema Drift on Every Webhook
def detect_schema_drift(vendor, event_type, payload, db_conn):
    """Compare incoming payload schema against registry, log changes."""
    current_schema = extract_schema_fingerprint(payload)
    schema_json = json.dumps(current_schema, sort_keys=True)
    schema_hash = hashlib.sha256(schema_json.encode()).hexdigest()

    # Check if we've seen this exact schema before
    existing = db_conn.execute(
        "SELECT id, field_inventory FROM payload_schema_registry WHERE vendor = %s AND event_type = %s AND is_current = TRUE",
        (vendor, event_type)
    ).fetchone()

    if not existing:
        # First time — register the schema
        db_conn.execute(
            "INSERT INTO payload_schema_registry (...) VALUES (...)",
            (vendor, event_type, schema_hash, schema_json, json.dumps(payload))
        )
        return {'status': 'registered', 'new_fields': [], 'removed_fields': []}

    # Compare against existing
    known_schema = json.loads(existing['field_inventory'])
    known_fields = set(known_schema.keys())
    current_fields = set(current_schema.keys())

    new_fields = current_fields - known_fields
    removed_fields = known_fields - current_fields

    # Log each new field as a drift event
    for field in new_fields:
        sample = get_nested_value(payload, field)
        db_conn.execute(
            "INSERT INTO payload_schema_changes (...) VALUES (...)",
            (vendor, event_type, 'field_added', field, current_schema[field], str(sample)[:100])
        )
        generate_schema_drift_alert(vendor, event_type, field)

    return {'status': 'compared', 'new_fields': list(new_fields), 'removed_fields': list(removed_fields)}

3.3 Integration Point

The schema drift detector hooks directly into the webhook ingestion pipeline with minimal overhead:

Square Webhook → Verify Signature → Parse JSON → detect_schema_drift()
→ Extract known fields → Store in transactions table → ETL to canary_metrics

The drift detection adds negligible overhead (~1ms per webhook) but ensures we NEVER miss a new field from any vendor. When a new field appears:

  1. Logged in payload_schema_changes table
  2. Fires an alert to the admin dashboard
  3. Includes field path, data type, and sample value
  4. Waits for a developer to review: integrate, monitor, or ignore
Schema Evolution Strategy

4.3 Updated Parser Function

The current parser in square_client.py extracts 10 fields. Here's the v2.0 function that extracts all 22+ forensic fields:

Python: parse_payment_to_transaction (v2.0)
def parse_payment_to_transaction(payment):
    """Normalize a Square payment object into our transaction schema.
    V2: Extracts digital forensic fields from full payload."""

    def _get(obj, key, default=None):
        if isinstance(obj, dict):
            return obj.get(key, default)
        return getattr(obj, key, default)

    # -- Existing extractions --
    refunds = _get(payment, 'refund_ids', []) or []
    is_refund = len(refunds) > 0
    refund_amount_cents = 0
    if is_refund:
        refunded_money = _get(payment, 'refunded_money', {}) or {}
        if refunded_money:
            refund_amount_cents = _get(refunded_money, 'amount', 0)

    amount_money = _get(payment, 'amount_money', {}) or {}

    # -- NEW: Digital forensic extractions --
    card_details = _get(payment, 'card_details', {}) or {}
    card = _get(card_details, 'card', {}) or {}
    device_details = _get(payment, 'device_details', {}) or {}
    risk_eval = _get(payment, 'risk_evaluation', {}) or {}
    app_details = _get(payment, 'application_details', {}) or {}
    tip_money = _get(payment, 'tip_money', {}) or {}

    return {
        # Existing
        'payment_id': _get(payment, 'id'),
        'amount_cents': _get(amount_money, 'amount', 0),
        'currency': _get(amount_money, 'currency', 'USD'),
        'status': _get(payment, 'status'),
        'source_type': _get(payment, 'source_type'),
        'is_refund': 1 if is_refund else 0,
        'refund_amount_cents': refund_amount_cents,
        'employee_id': _get(payment, 'team_member_id') or _get(payment, 'employee_id'),
        'location_id': _get(payment, 'location_id'),
        'created_at': _get(payment, 'created_at'),
        'updated_at': _get(payment, 'updated_at'),

        # NEW: Digital forensic fields
        'risk_level': _get(risk_eval, 'risk_level'),
        'card_fingerprint': _get(card, 'fingerprint'),
        'card_prepaid_type': _get(card, 'prepaid_type'),
        'cvv_status': _get(card_details, 'cvv_status'),
        'avs_status': _get(card_details, 'avs_status'),
        'device_id': _get(device_details, 'device_id'),
        'is_offline': _get(payment, 'is_offline_payment', False),
        'card_last4': _get(card, 'last_4'),
        'card_bin': _get(card, 'bin'),
        'customer_external_id': _get(payment, 'customer_id'),
        'order_external_id': _get(payment, 'order_id'),
        'square_product': _get(app_details, 'square_product'),
        'tip_cents': _get(tip_money, 'amount', 0),
        'card_type': _get(card, 'card_type'),
        'entry_method': _get(card_details, 'entry_method'),

        # Full payload preserved
        'raw_data': json.dumps(payment) if isinstance(payment, dict) else str(payment),
    }

This parser function is the "fingerprint extractor" at the heart of digital forensics. Every field it extracts is usable evidence.
